1. PROJECT OVERVIEW
================================================================================

The `scripts/` directory serves as a repository for standalone utility scripts
that automate various crucial tasks within the EWS Retention Platform project.
These scripts are designed to streamline data processing workflows, assist
in development tasks, and generate insights or metadata that complement the
main application's core functionality. They play a vital role in maintaining
data quality, governance, and providing foundational data structures for the
platform.

2. SCRIPTS
================================================================================

--------------------------------------------------------------------------------
2.1 generate_data_catalog.py
--------------------------------------------------------------------------------

- **Purpose**: This script systematically analyzes raw Excel data files located
  in the `data/raw` directory and programmatically generates a comprehensive
  `data/data_catalog.json`. This JSON catalog serves as a machine-readable
  metadata store, crucial for automated data ingestion, validation, and a
  detailed understanding of the structure of incoming data without manual
  inspection of each spreadsheet.

- **Location**: `scripts/generate_data_catalog.py`

- **Output File**: `data/data_catalog.json` (approximately 358KB when fully
  generated with all 10 data files)

- **Key Python Libraries Used**:
    - `pandas`: For reading Excel workbooks and manipulating DataFrames.
    - `os`: For file system path construction and directory operations.
    - `datetime`, `json`: For timestamping the catalog and JSON serialization.
    - `numpy`: For handling numpy-specific data types (`np.int64`, `np.float64`,
      `np.ndarray`) during JSON serialization.

- **Relationship to `data/data_catalog.json`**:
  This script is the sole generator of `data/data_catalog.json`. The output
  JSON file is consumed by the backend's data ingestion modules (e.g.,
  `backend/ingestion/schema_manager.py`) to inform data validation and
  processing rules. It should be re-run whenever raw data files are added,
  removed, or their schemas change.

- **Relationship to `DATA_MANIFEST.md`**:
  While `data/DATA_MANIFEST.md` provides a human-readable overview of data
  files and governance rules, `data_catalog.json` generated by this script
  provides the precise, machine-readable schema details used by the ingestion
  pipeline at runtime.

3.1 json_serializer(obj)
--------------------------------------------------------------------------------

**Purpose**: Custom JSON serializer function passed as the `default` parameter
to `json.dump()`. Extends the default JSON encoder to handle Python and numpy
objects that are not natively JSON-serializable.

**Implementation**:

```python
def json_serializer(obj):
    if isinstance(obj, (datetime, pd.Timestamp)):
        return obj.isoformat()
    if isinstance(obj, (np.int64, np.int32)):
        return int(obj)
    if isinstance(obj, (np.float64, np.float32)):
        return float(obj)
    if isinstance(obj, np.ndarray):
        return obj.tolist()
    raise TypeError(f"Type {type(obj)} not serializable")
```

**Type Conversions**:
| Input Type              | Output Type     | Example                          |
|-------------------------|-----------------|----------------------------------|
| `datetime.datetime`     | ISO 8601 string | `"2026-02-10T14:30:00"`          |
| `pandas.Timestamp`      | ISO 8601 string | `"2026-02-10T14:30:00"`          |
| `numpy.int64/int32`     | Python `int`    | `42`                             |
| `numpy.float64/float32` | Python `float`  | `3.14`                           |
| `numpy.ndarray`         | Python `list`   | `[1, 2, 3]`                      |
| Other types             | Raises `TypeError` | -                             |

--------------------------------------------------------------------------------
3.2 analyze_file(filepath, filename)
--------------------------------------------------------------------------------

**Purpose**: Processes a single Excel file to extract detailed schema and
metadata information for all sheets within the workbook.

**Parameters**:
- `filepath` (str): Full path to the Excel file (e.g., `data/raw/file.xlsx`)
- `filename` (str): Just the filename (e.g., `file.xlsx`)

**Returns**: A dictionary containing the file's metadata and per-sheet analysis.

**Implementation Flow**:

1. **Read Excel Sheet Names**: Uses `pd.ExcelFile(filepath).sheet_names` to
   get all sheet names in the workbook.

2. **Sheet Iteration**: For each sheet:

   a. **Intelligent Header Detection** (see Section 5):
      - Reads the sheet three times with `header=0`, `header=1`, `header=2`
      - Counts "Unnamed" columns in each attempt
      - Selects the header row with the fewest "Unnamed" columns

   b. **Student Identifier Detection** (see Section 6):
      - Scans column names against a list of student-related keywords
      - Records matching columns as `student_identifier_columns`

   c. **Time Column Detection** (see Section 6):
      - Scans column names against a list of time-related keywords
      - Records matching columns as `time_columns`

   d. **Column Metadata Extraction**: For each column:
      - `name`: Column header string
      - `dtype`: String representation of the pandas dtype
      - `null_count`: Number of null/NaN values
      - `null_percentage`: Percentage of null values (0.0 to 100.0)
      - `unique_count`: Number of unique non-null values
      - `sample_values`: First 3 non-null values from the column

3. **Error Handling**: If any exception occurs during file analysis, it
   catches the exception and records it in the catalog entry:
   ```python
   {"filename": filename, "error": str(e)}
   ```
   This ensures the script completes even if individual files are corrupt
   or unreadable.

**Output Structure Per File**:
```json
{
    "filename": "Engagement_Analysis.xlsx",
    "filepath": "data/raw/Engagement_Analysis.xlsx",
    "analyzed_at": "2026-02-10T14:30:00",
    "sheets": [
        {
            "sheet_name": "Learner Usage main dump",
            "header_row": 0,
            "shape": [1500, 25],
            "row_count": 1500,
            "column_count": 25,
            "student_identifier_columns": ["username", "learner_email"],
            "time_columns": ["last_login_date"],
            "columns": [
                {
                    "name": "username",
                    "dtype": "object",
                    "null_count": 0,
                    "null_percentage": 0.0,
                    "unique_count": 1500,
                    "sample_values": ["john.doe", "jane.smith", "bob.jones"]
                }
            ]
        }
    ]
}
```

--------------------------------------------------------------------------------
3.3 main()
--------------------------------------------------------------------------------

**Purpose**: Orchestrates the complete catalog generation workflow.

**Implementation Flow**:

1. **Define Data Directory**: Sets `DATA_DIR = "data/raw"` as the source
   directory for all raw data files.

2. **Hardcoded File List**: Defines a list of 10 specific Excel files expected
   to be present in the data directory (see Section 4).

3. **Catalog Aggregation**: Iterates through the file list, calls
   `analyze_file()` for each, and aggregates results into a `full_catalog`
   dictionary keyed by filename.

4. **JSON Output**: Writes the complete catalog to `data/data_catalog.json`
   using the custom `json_serializer`:
   ```python
   with open("data/data_catalog.json", "w") as f:
       json.dump(full_catalog, f, indent=2, default=json_serializer)
   ```

5. **Console Summary**: Prints a summary report including:
   - Total number of files analyzed
   - Total number of sheets processed across all files
   - Total number of rows processed
   - Unique student identifier column patterns found
   - Any files that produced errors

================================================================================
5. INTELLIGENT HEADER DETECTION ALGORITHM
================================================================================

Many raw Excel files from institutional systems have non-standard layouts
where the actual column headers are not on row 0. The script implements an
intelligent header detection algorithm:

```
For each sheet in the workbook:
    best_header_row = 0
    min_unnamed_count = infinity

    For header_row in [0, 1, 2]:
        df = pd.read_excel(filepath, sheet_name=sheet, header=header_row)
        unnamed_count = count columns containing "Unnamed" in their name

        If unnamed_count < min_unnamed_count:
            min_unnamed_count = unnamed_count
            best_header_row = header_row

    Use best_header_row for final data read
```

**Rationale**: When pandas reads an Excel file with the wrong header row,
columns that lack proper headers are automatically named "Unnamed: 0",
"Unnamed: 1", etc. By testing rows 0, 1, and 2 and selecting the one that
produces the fewest "Unnamed" columns, the script reliably identifies the
correct header row even in files with title rows or metadata above the data.

**Example**:
```
Row 0: "Student Performance Report - Trimester 1 2025"  (title row)
Row 1: "Generated on 2025-02-10"                        (metadata row)
Row 2: "Username | Email | Quiz 1 | Quiz 2 | Total"     (actual headers)
Row 3: "john.doe | john@... | 85 | 90 | 87.5"           (data)
```
In this case, header=0 would produce many "Unnamed" columns, header=1
would still be wrong, but header=2 would correctly identify the column
names, so `best_header_row = 2`.


================================================================================
6. STUDENT IDENTIFIER & TIME COLUMN DETECTION
================================================================================

The script uses keyword-based heuristics to automatically identify which
columns contain student identifiers and which contain time-related data.

**Student Identifier Keywords** (case-insensitive match against column names):
- `username`
- `email`
- `student`
- `user id`
- `org defined id`
- `learner`
- `roll`

A column is flagged as a student identifier if any of these keywords appear
as a substring of the column name (case-insensitive). For example, columns
named "learner_email", "Username", "student_id", "Org Defined Id" would
all be detected.

**Time Column Keywords** (case-insensitive match against column names):
- `date`
- `week`
- `time`
- `day`
- `month`
- `trimester`
- `semester`
- `timestamp`

A column is flagged as a time column if any of these keywords appear as a
substring of the column name. For example, columns named "last_login_date",
"Week-1", "total_time_spent", "semester_code" would all be detected.

**Purpose of Detection**:
- **Student identifiers**: Used by the ingestion pipeline to determine if a
  file contains student-level data (joinable to other student records) or
  aggregate/summary data (not joinable).
- **Time columns**: Used to identify temporal dimensions in the data,
  important for time-series analysis and feature engineering.

7. OUTPUT FORMAT (data_catalog.json)
================================================================================

The generated `data/data_catalog.json` follows this top-level structure:

```json
{
    "filename_1.xlsx": {
        "filename": "filename_1.xlsx",
        "filepath": "data/raw/filename_1.xlsx",
        "analyzed_at": "2026-02-10T14:30:00.000000",
        "sheets": [
            {
                "sheet_name": "Sheet1",
                "header_row": 0,
                "shape": [rows, cols],
                "row_count": 1500,
                "column_count": 25,
                "student_identifier_columns": ["username", "email"],
                "time_columns": ["date", "week"],
                "columns": [
                    {
                        "name": "column_name",
                        "dtype": "object|int64|float64|datetime64[ns]",
                        "null_count": 0,
                        "null_percentage": 0.0,
                        "unique_count": 100,
                        "sample_values": ["val1", "val2", "val3"]
                    }
                ]
            }
        ]
    },
    "filename_2.xlsx": { ... }
}
```

**Consumers of this file**:
- `backend/ingestion/schema_manager.py`: Reads the catalog to validate
  incoming data against expected schemas before ingestion.
- `backend/ingestion/pipeline.py`: Uses column metadata to determine
  data types and required transformations.
- `backend/services/core/data_ingestion.py`: References the catalog for
  sheet-specific ingestion logic.


================================================================================
8. USAGE & EXECUTION
================================================================================

This script is typically executed from the project's root directory. It is
recommended to run this script whenever:
- New raw data files are added to `data/raw/`
- The schema of existing files changes (e.g., new columns added)
- Files are archived or replaced with updated versions
- The ingestion pipeline reports schema validation errors

**Command to Run**:

```bash
python scripts/generate_data_catalog.py
```

**Prerequisites**:
- Python 3.x with `pandas`, `numpy`, and `openpyxl` installed
- Raw data files present in `data/raw/` directory
- Write access to `data/` directory for output file

**Expected Output**:

1. Console output with summary statistics:
   ```
   === Data Catalog Generation Summary ===
   Total files analyzed: 10
   Total sheets processed: 15
   Total rows processed: 12,450
   Student identifier patterns found: ['username', 'email', 'learner_email',
       'org_defined_id', 'student_id']
   Files with errors: 0
   Catalog saved to: data/data_catalog.json
   ```

2. Generated file: `data/data_catalog.json` (~358KB)

**Error Handling**:
- If a file is missing from `data/raw/`, it is recorded with an error entry
  in the catalog but does not halt execution.
- If a file is corrupt or unreadable, the error is caught and logged.
- The script always completes and produces output, even if some files fail.
