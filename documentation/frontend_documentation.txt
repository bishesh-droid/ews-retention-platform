1. PROJECT OVERVIEW
================================================================================

The frontend of the EWS (Early Warning System) Retention Platform is a
single-page application (SPA) built with React. It provides a user interface
for interacting with the backend API, visualizing student engagement data,
risk predictions, and intervention recommendations. The application focuses
on delivering an intuitive and responsive experience for administrators
and faculty.


================================================================================
2. TECH STACK & DEPENDENCIES
================================================================================

Framework:        React (JavaScript library for building user interfaces)
Routing:          React Router DOM (declarative routing for React)
HTTP Client:      Axios (promise-based HTTP client)
UI Framework:     Bootstrap (via react-bootstrap components)
Styling:          Tailwind CSS (utility-first CSS framework), custom CSS
Charting:         Chart.js (data visualization, via react-chartjs-2), Recharts
Animation:        Framer Motion (production-ready motion library for React)
Icons:            React Icons (popular icon packs as React components)
Virtualization:   React Window, React Window Infinite Loader (for efficient
                  rendering of large lists/tabular data)
Build Tool:       Create React App (via react-scripts)

File: frontend/src/App.js

The application uses `react-router-dom` for navigation between different

5. STATE MANAGEMENT
================================================================================

File: frontend/src/context/StudentContext.js

The application utilizes React's Context API for managing global state,
particularly for student-related data. This promotes a centralized and
efficient way to share data across multiple components without prop-drilling.

CLASS/COMPONENT: `StudentContext` / `StudentProvider`

`StudentContext` is created using `React.createContext()` and `StudentProvider`
is the component that makes student data available to any component nested
within it.

METHODS / HOOKS:

`useStudentData()`:
  - A custom hook that provides convenient access to the `StudentContext`,
    allowing components to easily consume student data and related state
    (loading status, errors, refresh function).

`StudentProvider` Component:
  - **`students`**: An array of student objects, each enriched with risk scores
    and other computed features.
  - **`loading`**: A boolean flag indicating whether student data is currently
    being fetched from the API.
  - **`error`**: Stores any error message encountered during data fetching.
  - **`totalStudents`**: The total count of students fetched.
  - **`loadStudents()`**: An asynchronous function, wrapped in `useCallback`,
    responsible for:
      - Setting `loading` state to `true` and clearing any previous `error`.
      - Fetching student data from the backend API using `fetchStudentsFromApi`
        (an alias for `getStudents` from `src/api.js`).
      - Updating `totalStudents`.
      - Iterating through fetched students to validate and potentially
        sanitize their `risk_score` using `validateRiskScore` from
        `src/utils/riskScoreValidator.js`.
      - Updating the `students` state.
      - Catching and setting any fetching errors.
      - Finally setting `loading` state to `false`.
  - **`useEffect()`**: Triggers `loadStudents()` once when the component mounts
    to initially populate the student data.
  - **`refreshStudents()`**: A callback that re-runs `loadStudents()`, allowing
    components to manually refresh the student data.

**6.1 Core API Utilities (frontend/src/api.js)**

File: frontend/src/api.js

This file provides core API utility functions, primarily utilizing the native
`fetch` API for key student data retrieval. It also includes mock data
generation for certain functionalities, suggesting that some backend endpoints
might still be under development or that the frontend uses these mocks during
specific development phases.

GLOBAL CONFIGURATION:
  - `API_BASE`: Determined by `process.env.REACT_APP_API_URL` or defaults to
    `http://localhost:8000/api/v1`. This configurable base URL allows the
    application to easily switch between development and production backend
    environments.

KEY FUNCTIONS:

`getStudents(limit)`:
  - Fetches a list of students from the `/api/v1/students/students` endpoint.
  - Implements a basic client-side caching mechanism (`cachedStudents`) to
    avoid redundant API calls.
  - Expects `risk_score` as a 0-100 percentage and `signal_breakdown` as
    0-1 probabilities from the backend, using this data "AS-IS".
  - Enriches each student object with `name`, `email`, and `program` fields
    derived from backend data.

`getStudentCount()`:
  - Retrieves the total number of students from the `/api/v1/students/overview`
    endpoint.

`getStudent(id)`:
  - Fetches detailed information for a single student by their ID from
    `/api/v1/students/students/{id}`.

`getStudentPrediction(id)`:
  - Retrieves a student's prediction data, internally calling `getStudent(id)`.
  - Transforms the fetched student data into a prediction-specific format,
    calculating `retention_likelihood` as the inverse of `risk_score`.

`getBatchPredictions(limit)`:
  - Fetches predictions for multiple students, iterating over the results
    from `getStudents()` and formatting them into prediction objects.

`getStudentRiskHistory(studentId, finalRiskScore)`:
  - **MOCK IMPLEMENTATION**: Generates a simulated risk history over time
    for a given student, for visualization purposes during development.
  - This function does NOT call a backend endpoint.

`getRecommendations(role, riskProfile)`:
  - **MOCK IMPLEMENTATION**: Returns hardcoded recommendations based on
    a specified role (faculty, sales, marketing) and risk profile.
  - This function does NOT call a backend endpoint.

`getAIAdvice(studentId, promptType)`:
  - **MOCK IMPLEMENTATION**: Returns hardcoded AI advice based on a prompt type.
  - This function does NOT call a backend endpoint.

`getInterventions(studentId)`:
  - **MOCK IMPLEMENTATION**: Returns a hardcoded list of past interventions
    for a student.
  - This function does NOT call a backend endpoint.

`createIntervention(studentId, interventionData)`:
  - **MOCK IMPLEMENTATION**: Simulates the creation of an intervention.
  - This function does NOT call a backend endpoint.

`generateReportNarrative(reportType, reportData)`:
  - **MOCK IMPLEMENTATION**: Returns a hardcoded report narrative.
  - This function does NOT call a backend endpoint.

**6.2 Service Modules (frontend/src/services/)**

Directory: frontend/src/services/

This directory contains specialized service modules that handle API interactions
for specific domains (e.g., `studentService.js`, `businessService.js`). These
services primarily use `axios`, providing a more structured and robust approach
to API calls compared to the direct `fetch` usage in `api.js` for some functionalities.
They abstract the API logic from the UI components, promoting reusability and
easier maintenance.

Example: `frontend/src/services/studentService.js`

This service specifically manages all student-related API interactions using `axios`.

GLOBAL CONFIGURATION:
  - `API_BASE_URL`: Similar to `api.js`, derived from `process.env.REACT_APP_API_URL`
    or defaults to `http://localhost:8000/api/v1`.
  - `axios.create()`: An `axios` instance configured with the `baseURL` and
    `Content-Type: application/json` headers, ensuring consistency for all
    requests originating from this service.

KEY FUNCTIONS:

`getAllStudents(limit)`:
  - Fetches a list of all students from `/api/v1/students/` with an optional limit.
  - Handles API errors gracefully by logging and re-throwing them.

`getStudentById(studentId)`:
  - Retrieves detailed information for a single student from `/api/v1/students/{studentId}`.

`getStudentCount()`:
  - Fetches the total count of students from `/api/v1/students/count`.

`getStudentPrediction(studentId)`:
  - Retrieves a specific student's risk prediction from `/api/v1/predictions/{studentId}`.
  - Uses `sanitizePrediction` (from `src/utils/riskScoreValidator.js`) to
    clean and normalize the prediction data received from the backend.

`getBatchPredictions(limit)`:
  - Fetches risk predictions for a batch of students from `/api/v1/predictions/batch`.
  - Iterates through the received predictions and applies `sanitizePrediction`
    to each one.

`getStudentsWithPredictions(limit)`:
  - An orchestrating function that calls both `getAllStudents()` and
    `getBatchPredictions()` concurrently using `Promise.all()`.
  - Merges the student data with their corresponding prediction data,
    validating the `risk_score` using `validateRiskScore`.
  - Returns an enriched list of student objects ready for UI display.

`searchStudents(query, students)`:
  - Performs a client-side search on an existing list of student objects
    based on their ID or name.

**6.3 Utility for Risk Score Validation (`frontend/src/utils/riskScoreValidator.js`)**

This utility module provides functions to ensure consistency and correctness
of risk score data across the frontend.

KEY FUNCTIONS:
  - `validateRiskScore(score, defaultValue)`: Ensures a risk score is a valid
    number within the expected range (e.g., 0-100) and provides a default
    value if invalid.
  - `sanitizePrediction(prediction)`: Cleans and normalizes a prediction object,
    ensuring all its fields (like risk scores, signal breakdowns) adhere to
    frontend display requirements. This typically involves clamping values
    to expected ranges and handling missing data.

10. PERFORMANCE OPTIMIZATIONS (react-window)
================================================================================

For displaying large datasets, particularly in lists or tables where thousands
of items might be present (e.g., student lists), the application employs
`react-window` and `react-window-infinite-loader`.

- **Windowing/Virtualization**: These libraries implement "windowing," meaning
  only the items currently visible within the viewport are rendered, rather than
  the entire list. This significantly reduces the number of DOM nodes, leading
  to improved performance, faster rendering, and lower memory consumption.
- **Infinite Loading**: `react-window-infinite-loader` extends this concept to
  support "infinite scrolling." As the user scrolls towards the end of the
  currently rendered items, it triggers a callback to load more data, providing
  a seamless experience for very large datasets without fetching all data at once.

**12.1  useStudentRisk (frontend/src/hooks/useStudentRisk.js)**

The primary hook for all risk-score-related operations.

EXPORTED CONSTANTS:

  RISK_CATEGORIES:
    CRITICAL  { min: 85, label: 'Critical',   color: '#DC2626' }
    HIGH      { min: 70, label: 'High Risk',  color: '#F59E0B' }
    MODERATE  { min: 40, label: 'Moderate',   color: '#FBBF24' }
    LOW       { min: 0,  label: 'Low Risk',   color: '#10B981' }

HOOK: useStudentRisk(studentId = null)

Reads the global student list from StudentContext and derives risk state
for the given studentId.

RETURNED VALUES:

  student             The matched student object (or null)
  riskScore           Validated risk score via validateRiskScore()
  riskCategory        RISK_CATEGORIES entry for this student
  riskDistribution    {critical, high, moderate, low} counts across ALL students
  loading             Boolean – true while an async API call is in progress
  error               Error message string if an API call failed

METHODS:

  categorizeRisk(score) -> RISK_CATEGORIES entry
    Classifies any numeric risk score into the appropriate category.

  getStudentsByCategory(category) -> Student[]
    Filters the global student list to those matching the given category.

  refreshPrediction(id?) -> sanitized prediction dict
    Fetches a fresh prediction from /api/v1/predictions/{id}.
    Applies sanitizePrediction() before returning.

  simulateWhatIf(id?, adjustments) -> simulation result dict
    POSTs to the what-if simulation endpoint with the given scenario.

**12.2  useIntervention (frontend/src/hooks/useIntervention.js)**

HOOK: useIntervention()
